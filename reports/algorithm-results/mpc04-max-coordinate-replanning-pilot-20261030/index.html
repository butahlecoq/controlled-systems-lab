MaxCoordinateGame: closed-loop MPC comparison

Four controllers repeatedly observe the full state, select a control, apply the current disturbance, and replan. The source-derived model is y'=z+v, z'=-y+u with terminal objective max(|y|,|z|).

Scope. Four scored steps, 16 complete binary disturbance histories per controller/horizon, 128 episodes, and 512 transitions. This finite-action and continuous-control QP pilot is not a reproduction of the source's continuous-action four-second RL task. Disturbance statements cover only the enumerated histories.

The nominal and finite-minimax controllers use discrete controls {−1,+1}. The QP controllers use continuous controls in [-1,1] and minimize the same terminal squared max-coordinate objective. Robust plans use one common open-loop control vector over every suffix, followed by replanning; they are not an in-horizon feedback tree. These different action domains do not establish a same-domain optimality comparison.

The independent checker replays all transitions, recomputes selected-plan values and terminal objectives, verifies the analytic one-step QP fixture, and checks retained HiGHS primal and dual residuals against their declared tolerances. Native failure and deadline fixtures verify zero-control fallback in the C++ episode loop. The finite policy-gap fixtures check fixed-plan/replanning/causal values 2/2/1 and scalar fixed-plan/replanning values 2/0.

Timings use five alternating process runs and are descriptive; no performance winner is claimed. There is no recursive-feasibility, stability, continuous-disturbance, or globally optimal causal-minimax claim. The upstream source is MaxCoordinateGame.py; its repository declares no license, and this report re-expresses the equations without copying source code.
