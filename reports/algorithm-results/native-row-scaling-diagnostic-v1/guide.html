Source-only reproduction guide

Check saved evidence before a new native replay

Return to the three-outcome report. The immutable ZIP includes numerical inputs, original and scaled rows, complete failure logs, exact executed C++ sources and source/hash receipts. It includes no compiler, ELF executable, static library, vendor source or SDK payload.

Check the saved data without an SDK

Unzip into a fresh directory. Python 3.11 or later is sufficient:

python source/check_evidence.py .

This recomputes exact rational row-scaling relations and checks the accepted full-state trajectory and original cost. It never runs a solver. Compare with the saved check result.

Provide a matching installed snapshot for a new attempt

The optional runner requires Linux and a caller-supplied installed CSL prefix matching all 240 hashes in the snapshot inventory. The original consumer used GNU C++ 16.2.1, CMake 3.31.6, Release and HiGHS 1.11.0. Required CMake targets are CSL::model_catalogue, CSL::nominal_quadratic_history and CSL::highs_convex. Component/header matches do not qualify a whole SDK.

python source/reproduce.py --sdk-prefix /path/to/matching/prefix  --build /path/to/fresh/local-build --output /path/to/fresh/new-attempts  --cmake /path/to/cmake-3.31.6

The build and output directories must be new. The runner verifies the prefix before and after, builds only the two small consumers with one job, holds an exclusive lock across the sequence and runs the analytic toy before models 23, 27 and 28. It retains every outcome. A different compiler creates new binary hashes and must remain a new attempt. The portable runner’s help path was checked during publication; it did not generate the captured attempts and was not used to repeat the numerical experiment.

Keep the policy and identities explicit

Each run uses a 300-second process-group wall timeout, inherited 300-second per-process CPU limit and 8 GiB per-process virtual-address-space limit, with one requested native thread. These are Linux RLIMIT scopes, not aggregate RSS limits. Numerical failures and timeouts remain records; neither model 27 nor model 28 in this capture is labelled infeasible.

The task remains the authored N=3, three-replan nominal profile. Only coefficients and intervals of selected constraint rows receive positive powers of two. Objective and variable bounds stay the same. Derived numerical program IDs carry a diagnostic suffix and retain the original problem/task reference. Never drop small coefficients or loosen the native threshold to imitate a successful replay.

Read the provenance boundary

The curation map lists all 93 original-file dispositions and original/public hashes. The executed C++ files retain exact captured bytes. Two executed local Python scripts are labelled location-token text projections; they are not portable executables. The portable checker and runner are supporting adaptations, distinct from those captured scripts. Original compiler, binary, source and SDK hashes remain in the execution receipt.

Source-only delivery leaves project binary-distribution terms and third-party binary redistribution gates unresolved. No binary installation or new package release is part of this report.

Regenerate presentation only

The shared framing and CSS are frozen snapshots for this version. The saved-data renderer checks HTML without optimization:

python source/render_snapshot.py --check

Plotting is optional and separate; source/plot_toy.py uses Matplotlib to draw the saved native point and analytic equality. It does not solve the toy. Library versions can change SVG serialization, so a new plot does not silently replace this locked version.
