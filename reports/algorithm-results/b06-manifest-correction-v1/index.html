Correcting the B06 scenario manifest

The original immutable capture remains byte-for-byte unchanged. Its scenario declares a 4×4 matrix but contains 15 entries. The corrected canonical scenario has 16 entries and records the source-supported final row [0, 0, -2, 1].

What the saved measurements represent

The measured driver at source commit 7df01ba3af5e4c46e867e2d737aca56a8f2461af hardcodes the complete 4×4 transition matrix. The separate integer oracle uses x4′ = x4 − 2x3, independently confirming the final row. The immutable capture’s only difference from the corrected canonical scenario is the missing zero in the manifest. The evidence supports associating those measurements with the hardcoded model, while retaining the original manifest defect in the record.

No solver was rerun. Existing solver results retain binary64 numerical assurance and are not newly recertified; this is not a historical reproduction of the paper.
