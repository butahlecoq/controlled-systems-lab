Reproducibility guide · Python standard library for verification

Verify this saved publication or create a new capture

This guide explains two different operations. Bundle verification checks committed capture-derived files and deterministic ZIP bytes; it does not invoke a solver. A new native capture runs all 35 cases and writes a new timestamped directory, leaving the historical capture untouched.

Verify the published bundle

Use a full-history checkout. The original native producer is bound to commit 635ac5ba59d230e2b09062690adc943ea6451568. The independent packaging renderer is pinned separately by the tracked publication-lock.json; that pin authenticates the renderer source, not the earlier native run.

git clone https://github.com/butahlecoq/controlled-systems-lab.git
cd controlled-systems-lab
TOOL_COMMIT=$(python3 -c 'import json; print(json.load(open("reports/algorithm-results/native-model-tracking-first-pass-v1/publication-lock.json"))["portable_renderer_commit"])')
git show "$TOOL_COMMIT:scripts/reports/stage_native_model_tracking_first_pass.py" > /tmp/stage-native-model-tracking-pinned.py
cmp /tmp/stage-native-model-tracking-pinned.py scripts/reports/stage_native_model_tracking_first_pass.py
python3 -B scripts/reports/stage_native_model_tracking_first_pass.py --check

The check requires only Python's standard library and committed repository inputs. It renders the bundle in memory and verifies the committed ZIP and adjacent checksum against the publication lock. The ZIP contains the generated HTML, guide, figures, raw records, input inventory, and checks; these generated members are not separate tracked site files. Sorted member names, fixed timestamps, and stored entries make the ZIP byte-reproducible. Its internal SHA256SUMS.json inventories every member except itself and the enclosing ZIP; the adjacent .zip.sha256 authenticates the archive.

Create a new native capture

Set CSL_PREFIX to an installed controlled-systems-lab prefix whose lib/cmake/CSL directory exports the native targets. This requires a configured C++ toolchain. The supervisor checks the installed prefix's SHA256SUMS inventory before running the cases.

cmake -S examples -B build/native-tracking \
  -DCSL_DIR="$CSL_PREFIX/lib/cmake/CSL" \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-tracking --parallel 1 \
  --target native_model_tracking native_discrete_models quadcopter_mpc
python3 -B scripts/reports/native_model_tracking_first_pass.py \
  --build build/native-tracking \
  --sdk-snapshot "$CSL_PREFIX" \
  --output-parent reports/algorithm-results/native-model-tracking-first-pass-v1

All 35 public discrete-model records are attempted. Model 21 retains the literal source task; the other 34 use authored educational tracking profiles. The configured limits are 120 seconds for source 21 and 60 seconds per other case. Failures and timeouts remain in the new capture rather than being omitted.

Each capture is written to a new UTC-timestamped directory. To verify a particular capture, pass its explicit directory; the verifier writes a sibling check directory and does not modify the capture:

python3 -B scripts/reports/verify_native_model_tracking_first_pass.py \
  reports/algorithm-results/native-model-tracking-first-pass-v1/capture-YYYYMMDDTHHMMSSZ

These educational tracking profiles do not claim a performance ranking, physical calibration, or nonlinear stability result.
