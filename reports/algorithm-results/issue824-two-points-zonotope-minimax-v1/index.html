TwoPointsOnParallelLines: zonotope candidate selection

This is a three-stage finite-catalog adaptation of the source differential-game environment. The selector ranks each fixed open-loop plan by its terminal zonotope factor-corner score, then replays only the selected plan through every finite disturbance history. It does not reproduce the upstream continuous-action RL problem.

Evidence and limits

The independent checker reconstructs the exact finite game, verifies all 27 candidate score rows by evaluating their stored terminal factor corners, and checks the selected plan's exact worst disturbance history. It checks four-dimensional zonotope coordinate bounds at every stage. Those checks do not prove full four-dimensional zonotope membership or a validated objective upper bound. The separate two-dimensional example checks complete inclusion of all finite terminal points in each axis-aligned zonotope.

The figure shows exact forward reachable sets, robust backward-winning states, their intersections, the box-selected and zonotope-selected outer set projections, and exact replay paths in both player phase planes. The fixed-plan policies use finite catalogs only; they make no continuous feedback optimality claim. The zonotope calls evaluate 884,736 factor corners each (27 plans × 32,768 corners). `perf` and `strace` were unavailable, so this is a known work count, not a profiler-confirmed CPU bottleneck.
