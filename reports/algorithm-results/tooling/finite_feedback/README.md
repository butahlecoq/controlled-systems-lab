# Finite feedback public-port report plan

The optional `csl_finite_feedback_report` executable runs four authored finite tables through `Registry<FiniteFeedbackPort>`, versioned method selection, prepared workspace creation, `run_registered`, and a literal whole-policy oracle. The fixtures are the whole-successor clipping trap, two-stage observed-state branching, an empty action catalogue, and a one-disturbance nominal case. The driver does not read private historical sources and makes no claim about L13's continuous rocket model.

`--smoke` emits one CSV row per fixture with `purpose=smoke`. `--measure N` requires 5–1000 repetitions, emits one excluded `warmup` per fixture, then round-robin `trial` rows with a rotating starting fixture. The measured steady-clock interval begins before registry construction and ends after public-port execution, reference-table comparison, and independent literal verification. It excludes fixture construction, CSV serialization, process startup, and destruction. Every row records the fixture, purpose, repetition, matched/failed status, initial winning flag, selected action indices, conditional branch indices where applicable, elapsed nanoseconds, method ID/version, and any diagnostic/stop detail. A nonmatching row causes a nonzero exit without suppressing other rows. This is a verified public-call interval, not isolated solver-kernel latency. The registered path recomputes the reference recurrence to reject false provider outputs.

The source/harness revision must be committed and independently reviewed before accepted collection. A collector should check a clean source commit, rebuild the exact Release executable, capture compiler/flags/CMake target graph and executable hash, and save a public-safe host/concurrent-work note before measurement. For MSVC x64, build with `CSL_BUILD_FINITE_FEEDBACK_REPORT=ON`, `CSL_ENABLE_HIGHS=OFF`, `CSL_ENABLE_QHULL=OFF`, and `BUILD_TESTING=OFF`; `NDEBUG` and C++20 must be verified from the generated build graph. Run `--smoke` first, then `--measure 7`, retaining raw stdout/stderr, exit status, and every row even on failure. The smoke and CTest runs are functional checks, not accepted measurements.

The collector should independently parse the four literal output profiles, verify exactly four warmups and 28 trial rows with each fixture repeated seven times, check method identity/version and nonnegative integer nanoseconds, and reject any failed, missing, duplicate or unexpected row. Hash the authored fixture source, driver, executable, and raw CSV. Preserve failed collections as nonpublishable evidence. A successful saved bundle needs versioned records, raw CSV/JSON, build and host provenance, literal results, suitable tables/figures, standalone HTML, an offline download ZIP, and exact-byte manifests. Compute per-fixture median/range from the seven accepted trials; do not claim a competitor speedup or a source-mapped limiter without measuring one. Mark unavailable internal phase/thread counters as unavailable. Rendering must use saved records without rerunning the executable.

Register the reviewed immutable bundle in the repository's report catalogue and Pages allowlist, merge after independent record/visual review, then verify the live HTML and downloads against saved hashes. Record the actual source commit and deployed URL in PR #352 and issue #5. No measured value or URL exists at this source/harness stage; report publication is a separate merge gate.
