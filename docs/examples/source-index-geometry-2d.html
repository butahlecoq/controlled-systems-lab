Two source-index methods inside the same 2D geometry operation

The input cloud is the unit square with four corners (IDs 0–3), a boundary point (ID 4), duplicate corner (ID 5), and the non-dyadic interior point (ID 6). QuickHull2D and the source-faithful BTULSHOR KPABEP/MODIF profile each propose original IDs. The affine-sum operation independently checks all generated points against those IDs with exact dyadic membership before it applies them. The checker is a separate invocation and its time/status is recorded separately.

Run the public-interface example

cmake -S . -B build/dev -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/dev --target csl_affine_sum -j1
cmake --install build/dev --prefix "$PWD/build/install"
cmake -S examples -B build/examples -DCMAKE_PREFIX_PATH="$PWD/build/install"
cmake --build build/examples --target source_index_geometry_2d -j1
./build/examples/source_index_geometry_2d quickhull
./build/examples/source_index_geometry_2d btulshor

The executable emits JSON with method identity, retained IDs, source trace/status, independent checker status and timing, and output vertices. It uses a 5,000 ms / 64-point checker budget. The input hull uses the declared square corners. The affine image and control sum are plotted from the saved QuickHull vertices. The saved BTULSHOR vertices match both plots. Tick labels show data coordinates, and the axes mark x=0 and y=0. This is a functional illustration, not a performance comparison or a claim of historical REACH reproduction. The legacy selection is the recovered Pascal source profile; no distinct baseline/modified source implementation has been identified.
