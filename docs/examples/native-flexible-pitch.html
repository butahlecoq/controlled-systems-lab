Synthetic flexible-pitch models: eight, twelve and sixteen states

An elastic vehicle couples rigid pitch, lateral motion, bending modes and liquid motion in its tanks. The 2016 Miass author document by Bulaev and Shorikov supplies this equation structure and the dimension formula n = 4 + 2(i + k). It does not supply a complete numerical calibration. These three reusable native cases therefore use explicitly synthetic constant coefficients, with no Soyuz calibration or historical reproduction claim.

Assemble the acceleration coupling first

The physical state begins with pitch angle θ (rad), pitch rate (rad/s), lateral position y (m) and lateral velocity Vᵧ (m/s). Each bending mode adds displacement and velocity (m, m/s); each tank adds slosh angle and angular rate (rad, rad/s). The kinematic closure ẏ = Vᵧ is explicit. The three cases have (i,k) = (1,1), (2,2), (4,2).

Equation (3) places tank angular acceleration in both rigid equations, and pitch/lateral acceleration in each tank equation. These coefficients belong in E. Bending displacement feeds both rigid equations; the actuator forces the bending modes. The native assembler retains E, Ã and B̃, checks the descriptor pivots and reconstruction residual, and solves E[A B] = [Ã B̃]. It refuses a singular or numerically unresolved descriptor before forming explicit dynamics.

The native zero-order-hold discretizer integrates ẋ = Ax + Bδ at 0.1-second intervals, through 40 transitions (4 seconds). Its RK4 step-doubling receipt estimates local numerical error; it is not a certified global error bound.

Full-state reachability before projection

Each stage has an independent control δ ∈ [−4°,4°], using the source Table 1 amplitude bound. A fresh input factor is retained at every transition. The full physical generator set is propagated with public native affine-image and Minkowski-sum operations; only afterward are the paired planes extracted. All 41 stages appear on every plane, including every bending and tank pair.

These forward sets do not impose the source's state bounds or its 35°/s actuator-rate limit. They answer reachability under independent amplitude-limited inputs. They are not stabilization trajectories, invariant sets or a safety certificate.

Projection boundaries use repeated two-dimensional segment sums and native QuickHull while retaining full-state witnesses. These witnesses are not a full high-dimensional vertex representation. The raw centre and generators preserve the complete unreduced zonotope.

Check the computation independently

The native checker evaluates a separate long-double augmented matrix exponential, then a backward support recurrence over every input interval. It compares this with the public generator propagation at every stage in coordinate and mixed directions. Separate planar support checks test each displayed boundary. The descriptor equations also have direct equation-residual and singular-matrix regression tests. Finite checks provide numerical evidence; they do not prove general certified inclusion.

The saved bundle retains descriptor and explicit matrices, all discrete stages, full-state generators, support checks, projection witnesses, stdout/stderr, and source/build/install identities. It contains no private original manuscript.

What the control interfaces support

The source's equation (12) is the interior running-state cost J₁ = ∑ from k=1 to N−1 of xₖᵀQxₖ, with normalized state weights. The current high-level history compiler accepts running control penalties and a terminal objective; it has no running-state quadratic term. This publication therefore supplies no solution of that stabilization objective. A terminal-only or control-only replacement would be a different problem.

The native one-step slew-memory lift can represent δₖ−δₖ₋₁ bounds exactly by augmenting the state with previous control. That adds one bookkeeping coordinate: 9, 13 or 17 states, distinct from the physical catalogue entries shown here. Recovery of a history checks the memory recurrence, while feasibility must also check its amplitude and increment sets. This capability does not by itself supply the missing running-state optimization integration.

Table 1's flight-segment-dependent state limits require a flight schedule and further numerical choices not supplied here. Its unsubscripted slosh-angle bound is not silently assigned to every tank. Full source stabilization remains a separate, open capability scope in issue 991.

The executable constructs the native model, propagates all physical coordinates, checks supports and writes CSV and screen/print SVG files. This path requires no Python model, HiGHS or Qhull.
