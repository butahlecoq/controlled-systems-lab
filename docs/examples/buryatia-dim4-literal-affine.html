Reachable-set approximations for the Buryatia Dim4 example

This page compares six native set representations through the seven affine updates written in the local Dim4.m script. Each state is four-dimensional. The three upper plots are coordinate projections of the full 4D sets; they do not turn the model into a 3D system.

Model and source identity

Deviation state: z₀ = (1, −1, 1, 1), around nominal state x̄₀ = (1, 1, 1, 1).

Parameters: a = 0.15, b = −0.8, c = 0.25; two independent controls vₖ ∈ [−1, 1]²; seven updates. The script uses degree-based sind/cosd.

At each stage, zₖ₊₁ = Aₖzₖ + Bₖvₖ, with Aₖ(1,2) = cosd(x̄₂,ₖ), Bₖ(1,1) = 1 + 0.5 cosd(x̄₁,ₖ), and the other entries listed in the complete model manifest.

Private MATLAB source is not included. Source SHA-256: f1b9868dac256a45f144ee5192ec8b789548b34c2be6be094005bcef8dc7293a. This is the literal seven-update affine script variant; it is distinct from the manuscript’s eight-step example and from the optional nonlinear-correction recurrence. The implementation and producer are at source commit 136e30f3. The terminal binary64 reference volume is 40808.165574887396, and its independent hull calculation found 756 extreme vertices. The native V record retains 16384 candidate rows and does not claim they are minimal.

    Reproduce the native record

    Configure the optional source-qualified report target, run its executable, then validate the output against the saved source variant and reference values:

    cmake -S . -B build/buryatia-dim4 \
  -DCMAKE_BUILD_TYPE=Release \
  -DCSL_BUILD_BURYATIA_REPORT=ON \
  -DCSL_ENABLE_HIGHS=ON -DCSL_ENABLE_QHULL=ON
cmake --build build/buryatia-dim4 --target csl_buryatia_dim4_report --parallel 1
build/buryatia-dim4/csl_buryatia_dim4_report --dim4-literal-affine \
  > buryatia-dim4-literal-affine-v1-records.json
python3 scripts/reports/buryatia/check_dim4.py \
  --exe build/buryatia-dim4/csl_buryatia_dim4_report
python3 scripts/reports/buryatia/check_dim4.py \
  --raw docs/examples/buryatia-dim4-literal-affine-v1-records.json

    The native record is numerical binary64 evidence. It does not certify real-arithmetic rounding, nonlinear reachability, feedback safety, or a performance comparison.
