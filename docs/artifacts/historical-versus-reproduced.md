# B04 historical versus reproduced evidence

The [B04 historical report](../research/b04-historical-comparison.md) is a
run-free export of the values in `B04-historical`. Its paired [HTML table](../research/b04-historical-comparison.html)
and [machine-readable JSON](../research/b04-historical-comparison.json) use the
same saved evidence. The report keeps the archival record separate from
`csl.comparison-record/1`, whose attempts represent executions of new
comparison configurations.

## Evidence tracks

The report has schema `csl.b04-historical-report/1` and carries the explicit
track `historical-only`. Its six reported Table 2 rows retain their source policy
labels, decimal tokens, coordinate precision, and source citations. A separate
field evaluates the original norm at each printed coordinate and gives an
exact-rational bound for the effect of coordinate display rounding. Neither
field is a reproduced solver result.

## Architecture decision

The exporter is a report-specific Python module under `scripts/reports`. It
consumes saved source files, validates their identities, and produces a closed
JSON document with Markdown and HTML views. The generated document keeps four
evidence states explicit: reported values, calculations at printed
coordinates, reproduced results, and current measurements.

The existing `csl.comparison-record/1` remains restricted to actual
`new-comparison` attempts. A public C++ table API would add a dependency from
`csl_artifacts` to `csl_input` and still need a report renderer. The narrower
saved-data export provides the requested table without package changes or a
run-shaped historical artifact. It records hashes for all three input files
and uses the exact audit producer for invariant and lower-bound evidence.

Restoration fields come from `docs/research/b04-consistency.json`, generated by
`docs/research/tools/check_b04.py`. That audit records the exact stock-invariant
contradiction and the unrestricted terminal-plane lower bound. The report
checks that the audit's manifest hash matches the B04 file it reads. It does not
repeat the invariant or lower-bound calculation.

The owner-recalled control interval `[-1,1]` remains a provisional hypothesis
from a separate adaptive demonstration. It is not assigned to the historical
manifest. The article-derived `b04-reference-v1` is a separate scenario. The
historical report marks reproduction and current runtime measurement
unavailable. It preserves the published `0.4` seconds only as historical
context.

## Rebuild

From the repository root, regenerate the checked-in HTML and JSON with:

```sh
python docs/research/tools/check_b04.py
python scripts/reports/b04_historical_report.py \
  --manifest benchmarks/scenarios/b04-historical.json \
  --consistency docs/research/b04-consistency.json \
  --archive-register docs/research/archive-selected-sources.json \
  --out docs/research
```

The generator reads saved files only. It has no solver, geometry, or network
dependency. The JSON records SHA-256 values for the manifest, consistency
audit, and archive source register. The Markdown, HTML, and JSON exports are
committed with the research documentation and linked from its reading guide.

## Delivery impact

This change adds a report-specific Python exporter and static documentation
files. It adds no public C++ API, dependency, or executable example, so no
package release is needed. The report does not make B04 executable and does not
alter the historical manifest or existing measured records.
