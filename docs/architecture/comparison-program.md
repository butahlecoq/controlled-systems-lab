Status: review draft for Wayfinder #390/#405. This document and proposed backlog remain behind the existing publication/implementation and no-merge review gate. The owner delegated detailed parameter selection; the defaults below incorporate that delegation and the owner-approved refinements in #399 / PR #410 comments, without changing the gate. ## Purpose and evidence boundary

Build a reproducible, staged comparison program across archived methods and the current controlled-systems-lab architecture. Historical published values remain immutable and retain their historical labels. New runs use corrected-track labels and disclose every port deviation. Missing historical inputs mean a synthetic fixture is a new experiment, never a reproduction. Archive files remain local and are not redistributed. Decision details: [fixture ladder #399](https://github.com/butahlecoq/controlled-systems-lab/issues/399), [old-side fairness #400](https://github.com/butahlecoq/controlled-systems-lab/issues/400).

The comparison harness must preserve failures, refusals, timeouts, unsupported cases, and incomplete evidence. The default enforced-comparison profile requests 300 seconds algorithm wall time and 8 GiB per attempt, with a 16 GiB suite allocation and at most two concurrent jobs; the larger local-exploration profile requests 1,800 seconds, 12 GiB per attempt, a 24 GiB suite allocation, and at most two concurrent jobs. These are initial conservative defaults, not completion guarantees. On the observed reference host (34,189,107,200 bytes, approximately 31.84 GiB; 12 logical processors), they leave OS headroom; lower suite caps if available memory requires it. The supervisor applies a machine-wide allocation across algorithm and checker jobs, not a fresh full allowance per worker. Use one solver thread by default; explicitly label threaded profiles and avoid oversubscription. Enforce wall termination over the supervised process tree. Memory is an enforced cap only when the platform/adapter can enforce it; report requested, enforced, observed, mechanism and scope. Windows Job Object committed/job memory is not RSS; Linux cgroup accounting likewise must be labeled by its accounting scope. If enforcement is unavailable, mark observation-only, not the same capped profile. A timeout/resource limit is an outcome row, never a missing sample. Apply the shared checker contract below after algorithm timing. For optimization and control, preserve family-specific independent checks; for approximation, diagnostics may run, but guaranteed inclusion claims require a complete sound oracle. Volume alone is never a correctness oracle. Timing uses tuned Release builds, alternating sides for at least five distinct repetitions, reports median and range, and retains a separate limiter profile. Historical values are not remeasured modern results. See `docs/architecture/published-algorithm-results.md` and [#398](https://github.com/butahlecoq/controlled-systems-lab/issues/398).

For hull and V/H, use dimensions 2, 3, 4, 8, and 16. The hull-reduction ladder uses 250, 1,000, and 5,000 points per cloud. V/H uses smaller dimension-specific starting clouds to limit facet explosion: d=2: 32/128/512; d=3: 32/128/512; d=4: 24/64/128; d=8: 16/24/32; d=16: 20/24/32. These are synthetic workload sizes, not runtime estimates or completion promises; retain timeout, refusal, and incomplete outcomes. Use deterministic unscrambled Halton unit-box points starting at index 1, plus three-seed IID tracks: standard multivariate normal N(0,I), uniform volume in [-1,1]^d, and uniform sphere surface generated by normalizing standard-normal vectors (reject exact zero norm). Use seeds 20261017, 20261018, and 20261019 per IID track. Pin the actual PRNG algorithm/version, normal transform, draw order, dtype, generator version, deterministic input serialization and materialized input hashes; a seed alone does not promise cross-language replay. Each side receives bit-identical shared inputs. Require at least five alternating tuned Release repetitions, separate from seeds, plus a separate limiter profile.

Per dimension, include a simplex with d+1 vertices, cross-polytope with 2d vertices, simplex plus controllable interior redundancy, and embedded rank-deficient duplicate/boundary cases. State exact analytic H/V pairs for structural cases. For boxes, H input has 2d inequalities and V output 2^d vertices; classify d=16 as a box stress case and do not require large facet enumerations. Extra stress beyond this matrix is opt-in. None of these synthetic cases claims historical reproduction. For synthetic control families, use n in {2, 4, 8}; for the n=4 fuel reference use horizons T in {4, 8, 16}. Preserve recovered historical cases as separate fixtures even when outside this ladder. The selected non-fuel double-integrator demonstration is horizon 3 and is not a substitute for this control ladder. These scopes follow [#399](https://github.com/butahlecoq/controlled-systems-lab/issues/399); the detailed defaults are selected under delegated parameter authority.

## Independent checker contract

A common checker interface runs after each completed algorithm, separate from algorithm timing, with independent family-specific checks. Its default budget is 5 seconds in the enforced comparison profile and 30 seconds in local exploration; make both configurable. Checker memory shares the job allocation and machine-wide concurrent cap. There is no mandatory slow proof pass. Retain evidence as **verified**, **incorrect**, or **inconclusive**: verified only when the stated scope is fully established by sound independent analytic, exact, or complete evidence; incorrect only on a concrete sound counterexample; timeout, memory exhaustion, unsupported checker, or incomplete evidence is inconclusive, not incorrect. Numerical feasibility/residuals and sampled support are diagnostics, not verified correctness; absent a sound witness they remain inconclusive. For source-index hull output, check every input point is covered, not merely mutual output containment. For H/V, establish both validity and completeness in both directions; the same converter round-trip is not the sole oracle. After failed/incomplete algorithm output, run partial diagnostics only and do not promote the algorithm status. Incomplete evidence is excluded from correctness-qualified winner claims. Witness replay alone cannot certify optimality or minimax. This contract specifies intended behavior; the checker is not implemented here.

## Old-side policy and task generality

Transcribe MATLAB, Python 2, and Pascal methods into Python 3 by default. Use C++ only when a fair common-runtime comparison or integration requires it; run native originals where inexpensive, including Free Pascal when available. Put each authorized port in `tools/legacy-ports/<artifact-id>/` with provenance, source identity, and adjacent `DEVIATIONS.md`. Accept a port only with reproducible inputs and an independent quality oracle. Artifacts blocked by unrecovered inputs (#2/#10) do not block other ports; omit historical comparison claims for those cases until recovery succeeds. [#400](https://github.com/butahlecoq/controlled-systems-lab/issues/400).

Demonstrate task generality with a two-state double integrator (position, velocity, scalar acceleration), horizon 3, convex box constraints on acceleration and intermediate state, and a quadratic terminal tracking objective. Run it through the same resolve/prepare/execute/report path and label it as a generality demonstration, not a historical comparison. Linearization around a reference trajectory remains future adapter work. [#401](https://github.com/butahlecoq/controlled-systems-lab/issues/401).

## Result contract

Paired results use a separate content-addressed `csl.comparison-record/1`, keyed by `ComparisonSpecId` and unique `ComparisonRunId`. Store a shared input-manifest hash, immutable `RunRecordRef` per side and attempt, historical/corrected track label, deviations, quality evidence, and explicit mathematical outcome plus termination status, including completed, refused, unsupported, failed, timed out, resource limited, cancelled, or incomplete attempts. Each side reference must resolve to its artifact identity: legacy artifact/source hash, port/runtime identity and deviation-log hash; modern module/provider ID and version; plus effective configuration, build/runtime fairness metadata, repetition index, and limiter-profile reference. If an immutable run record cannot supply these values, they belong in the comparison record. Retain every attempt. HTML is rendered from the immutable comparison record and is not itself the evidence source. The codec, matched-input/replay validation, failure retention, and renderer integration are backlog work, not existing capability. [#402](https://github.com/butahlecoq/controlled-systems-lab/issues/402).

No comparison-level speed or quality winner is claimed until both sides use matched inputs and their applicable independent oracle passes. Report inconclusive outcomes where evidence or timing cannot support a winner. Reproduction claims require recovered historical inputs and documented correspondence; a similar problem statement is insufficient. Later set representations (hybrid zonotopes, polynomial zonotopes, ellipsotopes) are excluded from this first comparison program; revisit them only after general approximation producers and independent inclusion verifiers exist. The estimator and replanning loop is also excluded: EXT-04 observation semantics alone do not define an estimator, and replanning runs must not be presented as globally optimal causal synthesis. Any such work requires a separate contract and remains behind issue #5 where its information pattern applies.

## Explicit exclusions and gates

- No reproduction claim for B03 or other artifacts without recovered arrays, seeds, and source correspondence.
- No ray/unbounded V/H parity in the first stage.
- No adaptive minimax or globally optimal causal feedback claim before issue #5 closes.
- No continuous-action minimax in the initial finite-catalog stage.
- No linearization or nonlinear-model comparison in this map.
- No hybrid zonotope, polynomial zonotope, or ellipsotope comparisons in the first program; reconsider only after approximation producers and independent inclusion verifiers are available.
- No estimator/replanning-loop comparison in this map; that needs separate observation and estimator contracts, with issue #5 governing adaptive-policy semantics.
- No redistribution of archive source code.
- The owner must review this summary and the final live backlog diff before the spec is published or issues are created/edited, as required by [#405](https://github.com/butahlecoq/controlled-systems-lab/issues/405).

## Disposition of the map’s former “Not yet specified” items

1. Geometry generators, sizes, distributions/seeds/serialization, structural cases, two resource profiles, shared checker evidence contract, and per-family quality checks are selected above; implementation remains backlog work.
2. The non-fuel task is the horizon-3 double integrator in #401; its role is a generality demonstration.
3. A second V/H converter is not required for bounded first-stage comparisons. Rays/unbounded inputs require a second usable side and independent round-trip/containment fixtures (#403).
4. The general substitution sweep belongs as an extension of existing EXP-02 #94 after its scope is reviewed; no duplicate is proposed.
5. Two-sided comparison evidence uses the new `csl.comparison-record/1` defined above (#402); schema and publication implementation remain backlog work.
6. Hybrid/polynomial zonotopes and ellipsotopes are excluded from this first program; reconsider only after existing approximation producers and independent inclusion evidence mature.
7. Adaptive minimax is gated by issue #5 and excluded from the first fixed-plan finite-catalog stage (#404).
8. Linearization-near-reference work is outside this map and requires its own nonlinear input, residual-bound, and validity contracts (#401/#397).
9. Estimator/replanning work is outside this map; EXT-04 observation semantics do not supply an estimator or prove globally optimal causal control (#395).

These dispositions replace the map’s stale “Not yet specified” bullets. They are proposed edits to #390 for owner review, not yet applied. Detailed parameter selection has been delegated; this does not waive the existing review/no-merge gate.
