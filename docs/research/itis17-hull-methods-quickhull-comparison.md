# ITIS'17 hull methods and QuickHull comparison

## Finding

QuickHull and the two ITIS'17 methods are comparable on the *same finite 2D point clouds* for hull correctness and, with clearly separated timing scope, runtime. They are different algorithm families: QuickHull is geometric divide-and-conquer with exact orientation on represented binary64 coordinates; A43 and A44 are LP/simplex point-cloud reducers. Do not call either LP method QuickHull, nor treat the ITIS'17 reachability experiments as QuickHull measurements. QuickHull's 2D-only contract, original-index output, duplicate/collinear policy, and exact represented-coordinate predicates are specified in [`quickhull-2d.md`](../contracts/quickhull-2d.md#L3-L38); implementation uses farthest-point recursion and no LP query ([`quickhull_2d.cpp`](../../src/geometry/hull/quickhull_2d.cpp#L50-L80)).

## Paper methods and provenance

**A43** is V. V. Bulaev and A. F. Shorikov, “Модификация общего рекуррентного алгебраического метода построения областей достижимости линейных дискретных управляемых систем” (2017), source-register entry [A43](archive-selected-sources.json), SHA-256 `a90a3e404807238886122dfdfc91a5f18697949137a8d9744af7180508de848a` (11 PDF pages). Section 2, PDF p. 4, formulates point-extremality as convex-combination LP feasibility over the other points. Section 3, PDF pp. 5–7, uses an artificial basis; at the end of phase I it checks nonbasic point columns for nonnegative normalized coordinates over the feasible basis and removes certified points in a batch. It also changes the entering-column tie choice to the greatest norm and uses a 2D example (PDF pp. 6–7) to motivate the claim that the resulting basis points are hull vertices. The paper describes why the classical tie rule can yield a feasible basis of nonvertices, but offers no general degeneracy/pivot proof for the greatest-norm refinement. These pp./section references and method details were checked against extracted text from the registered primary artifact.

**A44** is A. Yu. Goranov and A. F. Shorikov, “Модифицированный рекуррентный метод построения области достижимости линейной дискретной динамической системы” (2017), source-register entry [A44](archive-selected-sources.json), SHA-256 `493917da7d8ac669a470a978780a2ca269ce9da1b594365f49c6ebd572388fd7` (11 PDF pages). Section 3, PDF pp. 4–5, defines the all-points convex-combination LP test. Section 4, PDF pp. 6–7, defines the box-center normalized-distance ordering, assumes the first `k+1` points are farthest and seeds the candidate set, incrementally tests each remaining point against that set, then reruns the LP check for every retained candidate. The ordering text is internally inconsistent: the section first says “in order of increasing distance” and shortly after says the first `k+1` are “most distant” (section 4, PDF p. 6). The metric is described using normalized displacement and the Euclidean norm. These pp./section references and method details were checked against extracted text from the registered primary artifact.

**Primary-source access:** the registered A43/A44 artifacts were inspected read-only, and their hashes were recomputed against the source register. The archival PDFs remain local and are not redistributed with this note. PDF pages cited here mean one-based PDF page indices (the printed page footer may differ). The papers describe hull reduction as a subproblem in reachability construction; a fixed point cloud is a valid isolated comparison target, but it does not compare the full recurrence or reachability workload.

## C++ correspondence and current evidence

The existing **OPT-06 basis reuse** reducer is related to A43, but differs from the paper's per-candidate artificial-basis sequence and does not apply the largest-norm tie rule. Current `csl.hull.itis17.a43-certified-basis-reuse` wraps OPT-06 and runs a final LP recheck; its code records that tie policy as unapplied ([`itis17_reducers.cpp`](../../src/geometry/hull/itis17_reducers.cpp#L13-L35)). The existing **OPT-07 ordered membership** method is related to A44's ordering/filtering, but is not a paper port. Current A44 adaptation uses a farthest-first normalized Euclidean score, seeds `dimension+1` points, incrementally tests the rest, and rechecks ([same source](../../src/geometry/hull/itis17_reducers.cpp#L53-L137)). The A44 direction and norm choices are adaptation decisions, not settled facts from the source. Shared LP deletion is conservative: a floating LP solution alone does not authorize removal; exact dyadic verification is required ([`hull-reduction.md`](../contracts/hull-reduction.md#L9-L34)).

No matching Pascal implementation is present in tracked repository source/history or the registered A43/A44 materials. The source register's A06 `btulshor.pas` is a separate legacy item; its description does not establish correspondence to A43/A44. Therefore no initial Pascal version, exact paper-to-code mapping, or historical runtime can be verified from the available registered sources.

PR [#755](https://github.com/butahlecoq/controlled-systems-lab/pull/755) is an **open, report-only** EXP-02 publication PR, not a completed paper-faithful comparison. Its r1 report compares QuickHull, LP baseline, basis reuse, ordered membership, A43 adaptation, and A44 adaptation on two deterministic interior-heavy 2D square clouds (64 and 256 points; five measured repetitions plus warmup). The README says all 60 attempts passed independent hull checks, but only QuickHull, basis reuse, and A44 completed consistently; performance is explicitly inconclusive because workspace creation is excluded and no limiter/source-function profile is available ([r1 report README](../../reports/algorithm-results/exp02-it17-dyadic-interior-20261027-r1/README.md)). The newer A44 v2 pilot changes method identity to farthest-seeded normalized Euclidean ordering and still labels results exploratory ([v2 README](../../reports/algorithm-results/exp02-it17-a44-paper-order-20261027-r2/README.md)). The PR body likewise says it does not finish issue #94's broader scope.

## Next benchmark design and gaps

- Keep separate method IDs for QuickHull, generic LP baseline, OPT-06, OPT-07, A43 adaptation, and each A44 version. Do not relabel OPT-06/07 results as paper results.
- Start with 2D shared clouds for direct QuickHull parity; separately run LP methods in higher dimensions only where no QuickHull comparison is claimed. Preserve original point IDs and define one duplicate/collinear policy for geometry-level comparison.
- Cover interior-heavy, boundary-heavy/all-extreme, duplicate, edge-collinear, fully collinear, symmetric/tied-score, zero-width-axis, and permuted inputs over a size ladder. Independently check hull equality. Report LP completion, certificates, retained-point count, recheck calls and failures separately from QuickHull orientation/partition work.
- State the exact represented-coordinate and solver-tolerance semantics. Any disagreement caused by tolerance is a correctness mismatch, not an equivalent result. Time the same end-to-end interval or disclose setup separately; retain failed attempts and use the repository's evidence gates before making performance claims.
- The major unresolved source gap is the original Pascal implementation. Until the source (and build/runtime context) is recovered, results can compare the papers' reported algorithm ideas and present C++ adaptations, but cannot establish historical Pascal behavior or runtime.

This note is source research only; no benchmark was run.
