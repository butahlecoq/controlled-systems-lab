# Minimax comparison coverage (issue #394)

Assessment against `origin/main` at `820373c` (2026-10-17). This is a factual coverage audit, not a choice of game semantics or benchmark. Here **fixed plan** means the complete control sequence is selected before uncertainty; **causal** means each action can depend only on information available before that action; **receding horizon** means repeatedly solving a remaining-horizon fixed-plan problem and executing its first action. These classes are not interchangeable.

## Exact gaps before old-vs-new comparisons

1. **Old-side ports / reproducibility:** `MinimaxOpenLoopControl.py` contains the audited worst-case-oracle defect (minimizes convex cost then negates it; L19 counterexample returns `-0.0` where true max is 1) and Python 2/float32 simplex limitations. `ClosedLoopControl.py` relies on missing `OpenLoopControl.py`; MATLAB A08/A09/A02 and `results.mat` are not a single executable canonical bundle. `docs/research/legacy-audit.md`, `source-map.md`, and #2 record these gaps. A modern port must retain the frozen legacy result separately rather than treating its reported optimum as valid output.
2. **Continuous actions:** current finite oracle is specifically an ordered finite action catalogue (contract `finite-action-minimax.md:6-10,12-20`). It supplies a discrete fixed-plan numerical reference, not an oracle for continuous-action minimax. No global continuous adversarial solver for either fixed plans or causal policies is delivered by this code path.
3. **Bounded versus statistical uncertainty:** EXT-01 and the finite oracle represent explicit bounded compact set-valued disturbances and deterministic worst-case maxima. They do not estimate probability distributions, confidence regions, chance constraints, or expected cost. A statistical source must define its data/distribution and target separately; bounded envelopes are not statistical evidence and vice versa.
4. **Disturbance semantics:** supported fixed-plan paths require nonempty independent stage disturbance sets (rectangular product); finite oracle explicitly rejects unsupported/correlated forms. Coupled, state/action-dependent or adversarially selected distributions are not implied. Specify whether disturbances are chosen independently per stage, subject to a shared budget, or revealed before/after actions.
5. **Stage constraints:** B07's robust feasibility is whole-tube containment at each constrained stage. A comparison must pin exact stage indices including x0/xT, admissible action/state sets, and whether infeasible plans are excluded or violations are penalized. Clipping a reachable set to the safe set is not robust feasibility. The existing finite feedback safety game is a separate, finite-state contract, not a continuous-polytope cost-optimal variant.
6. **Adaptive gate (#5):** must settle exact policy authority and information timing: full state or measurements; when state becomes available; action before disturbance; whether causal policies can depend on past controls/state; whether reported “adaptive” result is a fixed-plan first-action replanner or a global policy-tree optimum; and whether objective is executed-policy worst case over whole history. Replanning guarantee cannot be upgraded to global optimality; issue #5 remains open.
7. **Baseline readiness:** B06 disturbance details/control sign are unresolved; B07 disturbance/physical inputs need recovery; B08 exact printed-data check differs from paper and is only the displayed rounded problem; B09 is internally inconsistent and its control/error/integration data remain incomplete (`baselines.md`). No single old-vs-new comparison across these should collapse separate model revisions.

## Scope challenges / facts qualifying the plan

- A code-level finite fixed-plan minimax oracle closes only one operand: it does not settle the larger “minimax / adversarial second player” question for continuous actions, causal feedback or statistical uncertainty.
- “Adaptive” is not a sufficient policy-class label. A08/L13's replan-and-execute-first-action rule is causal but generally distinct from a globally optimized causal policy; #5's example proves a strict gap in a small model.
- The finite-feedback module's output is a safety/winning relation. Reading it as a cost-optimal feedback controller would overstate what it computes.
- B06/B07/B08/B09 are not uniform replicates: constraints, horizon, action catalogues, uncertainty, criteria and archived inconsistencies differ. Cross-version runtime/value comparisons would be confounded.
