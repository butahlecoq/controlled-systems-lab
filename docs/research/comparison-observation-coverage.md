## Exact gaps before old-vs-new comparison

1. **No known old-side estimator/observer.** L07 supplies a descriptor observation equation, not an executable filter/controller implementation. The recovered adaptive A08 and Python L16 are control/replanning sources, not an estimated-state observer with explicit noise covariance/set, innovation/update law and initial-estimation semantics. The legacy audit/source map list no such implementation; “not recovered” is not a claim that none existed outside the searched archive. A comparison must either recover and identify an actual old estimator or report that the legacy observation side is unavailable—not silently substitute exact state.
2. **EXT-04 is partially delivered, still open (#68).** Completed slices: scheduled observation model, sampled replay callbacks, independent partial/noisy and no-channel tests, fixed-source measured report, and finite enumerated nonanticipative policy table (#385). Remaining issue acceptance: general initial-set synthesis; continuous-set policy-family evidence; correlated initial/external information beyond rows; complete estimator/callback lifecycle and nonanticipativity closure; constraint feasibility and policy optimization/certification. The current issue comments explicitly say #68 remains open.
3. **Estimator/replanning-loop boundary:** replay accepts an arbitrary estimator callback and one-step controller callback, but does not define the estimator algorithm, uncertainty-set update, replanning objective or policy globality. A08/L13 repeatedly solve a remaining-horizon fixed-plan problem, apply one first action, then observe/recompute; this is receding-horizon execution, not a globally optimized observation-based policy (`docs/research/adaptive-policy-proof-audit.md`, “Recovered implementation evidence: A08/A09”; `feedback-contract-followup.md`). A sampled callback closure is not itself a nonanticipativity proof; finite-policy tables constrain the action to released histories only over listed scenarios.
4. **Issue #5 information-pattern gate:** settle which observations are available before each action, whether state is exact or a set/hypothesis, when disturbance is revealed, whether the same action must apply to states indistinguishable under a common history, and whether the target claim is replay, robust feasibility, receding-horizon guarantee or global causal optimum. Distinguish `∃u∀w` from `∀w∃u`; only the former is control-before-disturbance. Add measurement/noise and model-error quantifiers plus the permitted correlation between initial state and exogenous histories. The audited source-specific policy distinctions in `adaptive-policy-proof-audit.md` and current #5 remain open.
5. **Initial-state scope:** one replay takes one concrete `x0`; existential finite policy evidence checks one caller-selected row, universal finite evidence checks all rows given. It does not synthesize one policy for all continuous initial states nor prove sampled rows cover a set. Existential “some initial state has a witness” must not be presented as a uniform guarantee.
6. **What present results support:** observation schedules/timing and concrete finite trajectories can be compared on the same identified model, supplied initial state, external sequence and measurement-error samples, if old values can be produced. Finite nonanticipativity can be compared on the same enumerated scenario list. No result supports universal continuous initial-set/disturbance behavior, estimator accuracy, robust constraint feasibility, global observation-policy optimality, or legacy old-vs-new estimator comparison.

## Scope challenges / facts qualifying “sequenced last”

- The general observation model and timing contract were designed early and are already implemented as a scheduled affine model subset; “last” can only accurately describe later observation-based control/synthesis scope, not all observation-related engineering.
- EXT-04 now has a shipped finite observation-history policy evaluator. Treating the entire observation family as wholly unimplemented would ignore this concrete slice; treating it as a general feedback solver would overclaim it.
- A finite scenario list can demonstrate callback nonanticipativity only for its enumerated observation histories. It cannot establish continuous all-initial/all-disturbance behavior or validate a state estimator.
- Hybrid extension #156 is a separate future mode/invariant/guard/reset profile. Its existence neither fills nor blocks the observation estimator gap.
