# Qhull 8.0.2 integration review

Date: 2026-10-18. Scope: source audit of the selected Qhull conversion integration for architecture issue #7. This is a source review, not a build, race test, benchmark, packaging audit of an installed artifact, or approval of the project's distribution license.

## Verified findings

- **Selected behavior is narrow.** The product registers `csl.conversion.qhull` on `ConversionPort`. The contract supports cross-representation conversion for bounded H/V polyhedra with finite binary64 input. H-to-V delegates feasibility, boundedness and relative-interior queries to the selected `LPPort`, then uses polar facet enumeration; V-to-H enumerates facets in affine coordinates. Rank zero and one have direct paths; same-representation conversion returns the original handle. Nonempty V rays, unbounded H-to-finite-V conversion, ambiguous rank, validated assurance and other output representations are rejected or unsupported. This matches the inspected dispatch and admission paths in `qhull.cpp` and `polyhedral-conversion.md`.
- **Numerical claims are limited.** The adapter calls Qhull with fixed `"qhull Qx"`. Qhull v8.0.2 documents floating-point roundoff and says its error bound is empirical rather than theoretical ([precision discussion](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/html/qh-impre.htm), [Qx option](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/html/qh-optq.htm#Qx)). The adapter publishes numerical residual evidence and explicitly says its finite residual checks do not prove global set equality. Only its special ambient-one H-to-V path adds an exact-dyadic interval coverage bound. There is no exact or validated general-dimensional H/V conversion claim.
- **Coordinates and integer widths.** Upstream `user_r.h` sets `REALfloat` to zero, making `realT`/`coordT` double, and defines `qh_POINTSmax` as `INT_MAX-16`; `libqhull_r.h` declares `qh_new_qhull` with signed `int dim` and `int numpoints` ([user_r.h](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/src/libqhull_r/user_r.h), [libqhull_r.h](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/src/libqhull_r/libqhull_r.h)). The adapter now checks each generated Qhull call against `qh_POINTSmax` and the signed-int dimension range before converting either to `int`; request admission also checks raw input row/point counts against `INT_MAX`. `QhullOptions` permits caller-selected `max_ambient_dimension` and `max_input_rows`, but no default cap, output-size cap, facet cap, memory cap, or global combinatorial budget is implemented. Host allocation and intermediate Eigen sizes remain practical limits.
- **Cancellation is boundary-only.** The wrapper checks cancellation/deadline before generated LP work, after selected LP work, and after the synchronous Qhull call returns. The call to `qh_new_qhull` has no stop-token argument in the pinned public header. Thus cancellation cannot interrupt a running hull computation; the stop can prevent publication only when control returns. Existing contract tests cover provider rejection and stops before native workspace creation, but no deterministic test cancels during Qhull itself.
- **Reentrant does not establish thread-safe integration.** The adapter creates a local `qhT`, diagnostic streams and coordinate storage for each hull call, avoiding shared `qhT` state by construction. Upstream's v8.0.2 reentrant documentation nevertheless labels Qhull not thread-safe and forbids concurrent calls on the same `qhT*` ([reentrant notes](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/html/qh-code.htm#reentrant), [header](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/src/libqhull_r/libqhull_r.h)). I found no Qhull conversion test that runs multiple conversions concurrently. Separate local contexts make independent-instance concurrency plausible, but it remains an inference, not a verified product guarantee; thread safety of the selected LP provider and `observe` callback is also outside this Qhull source review.
- **Build and platform evidence.** CSL fetches the v8.0.2 source archive from the Qhull GitHub codeload endpoint and pins SHA-256 `8774e9a12c70b0180b95d6b0b563c5aa4bea8d5960c15e18ae3b6d2521d64f8b` in `cmake/QhullDependencies.cmake`. It compiles a fixed list of `libqhull_r` C files into a static private target and links `m` outside MSVC. The adapter needs HiGHS enabled for its default configuration, though it accepts a caller-provided LP registration. The repository's `native.yml` matrix configures the default full build with MSVC on Windows and GCC 13/Clang 18 on Linux; it builds and runs CTest. That is evidence of intended CI coverage, not evidence that these jobs passed in this review. Upstream README documents CMake and Windows builds but does not establish every compiler/configuration used by CSL ([README](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/README.txt)). No compiler or test command was run for this research task.
- **Notice handling.** Upstream `COPYING.txt` requires intact copyright notices and redistribution of that text with Qhull copies, including software products that include Qhull; for modified Qhull, it requires a modification notice and notice of source availability ([COPYING.txt](https://raw.githubusercontent.com/qhull/qhull/v8.0.2/COPYING.txt)). CSL installs the unmodified upstream file to `share/CSL/notices/Qhull-8.0.2`. The source list and binary packaging inventory were not audited for every included Qhull file. The reviewed base's installed-package script explicitly checked the JSON notice but had no corresponding Qhull assertion; this PR adds a conditional installed-prefix check when Qhull is enabled. That check verifies configured installation presence, not every downstream packaging workflow or legal sufficiency. This review does not decide the license for CSL.

## Claims not established by this audit

The source and tests do not establish general polyhedral operations, exact/validated equivalence, completeness of the numerical residual audit, robust behavior for every degenerate or ill-conditioned input, bounded run time or memory, prompt in-call cancellation, an output-size policy, independent-instance thread safety, or final package compliance. The v8.0.2 Qhull profile is a conversion component; it does not settle architecture issue #7's broader polyhedral backend and resource-policy requirements. The broader operation gaps listed in ADR 0002 remain separate work.
