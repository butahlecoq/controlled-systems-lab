## Smallest supported robust predecessor

The following **proposed** contract is narrower than arbitrary `InformationPattern::feedback`. At stage `t`, take an exactly known state `x` available before the action; a fixed, ordered, finite action catalog `C_t` (possibly empty); a fixed nonempty compact disturbance set `W_t`; closed safe set `X_t` and next winning set `S_{t+1}`; and a continuous transition `f_t`. Disturbance choices are rectangular across stages. The immediate decision cannot depend on the current disturbance. Define

```text
Q_t = { (x,u) : x in X_t, u in C_t,
                 {f_t(x,u,w) : w in W_t} subset S_(t+1) }
S_t = { x : some u has (x,u) in Q_t }
S_T = X_T intersect terminal_target
```

Thus the query is `exists u forall w`; **one** action covers the entire successor uncertainty set. Return the empty winning set if `C_t` is empty or no action works. Do not replace containment by `successors intersect S_(t+1) != empty`: the [audit’s scalar example](adaptive-policy-proof-audit.md#robust-predecessor-and-supported-feedback-operands) has successors `[-1,1]` and target `{0}`, so the intersection is nonempty although the robust predecessor is empty. An empty disturbance domain is invalid input, since vacuous universal truth would change the game.

For this fixed-domain contract, the audit proves closed feasible-state fibers and a Borel selector that chooses the first feasible catalog action; it does **not** prove that this selector minimizes a terminal cost. Backward induction with exact sets and transition proves robust safety and terminal arrival for states in `S_t`. An inner approximation needs a valid action witness whose **actual** entire successor set lies in the next certified inner winning set to retain that guarantee. An outer approximation alone cannot authorize a safe action; only a state proved outside the outer predecessor is ruled out. Record direction, assumptions and numerical support explicitly. The existing [nominal predecessor API](../../include/csl/reachability/nominal_predecessor.hpp) is an existential projection without a disturbance operand, and its [implementation](../../src/reachability/nominal_predecessor.cpp) leaves the authored real-model claim unestablished after binary64 row pullback; it is not this robust predecessor.

For an affine transition and a **convex H-represented** next winning set, finite exact disturbance vertices give a concrete special case: each H-row must hold for every disturbance vertex for a *fixed* candidate action. This follows from affine propagation and linear maximization on a compact polytope. It does not cover a nonconvex winning set by checking only vertices; the audit gives `S={-1,+1}` and successors `[-1,1]` as a counterexample. Binary64 implementation still needs certified enclosure or an explicitly weaker numerical claim. General state/action-dependent uncertainty, coupled histories, continuous action minimization and value-optimal measurable selectors remain outside this bounded contract.

## Intake and result obligations

1. At the model boundary, require an explicit uncertainty structure and observation timing. The current [resolver](../../src/problem/resolved.cpp) admits stage-product uncertainty, rejects coupled/fixed-parameter alternatives and accepts the coarse `feedback` tag; the [observation records](../../include/csl/contracts.hpp) describe measured/available times. None of those fields alone establishes exact four-state reconstruction or the minimax policy class.
2. For the exact-state contract, require proof that `x_t` is available before `u_t`; treat noisy/output-only observations as an information-set problem in which **one** action must work for every state consistent with the same observation. Do not call the exact-state predecessor separately at each indistinguishable state. See the [audit’s information-set boundary](adaptive-policy-proof-audit.md#robust-predecessor-and-supported-feedback-operands).
3. Bind any nonlinear physical claim to a justified additive/model-error enclosure over all reached states, sensor error, action accumulation and decision timing. L13 Algorithm 3 step 5 mentions nonlinear evolution or processed sensors; A08 records simulated state and accumulates the throttle increment. Neither source supplies that enclosure or a four-state measurement proof. Until then, report a discrete surrogate-model guarantee only.
4. Separate outcomes: `unsupported` when the requested information/uncertainty structure exceeds the contract; `infeasible` only after a supported exact emptiness proof; `unestablished` for numerical inclusion without a certificate; and a winning set plus causal action witness only with the claimed evidence. A full causal minimax value would additionally need a value recursion, attainment/selector argument and whole-history cost verification.

An implementation review should exercise literal observable outcomes for the audit's strict-gap and interior-worst-case example, whole-set clipping failure, tie actions, empty catalog, nominal equality, and any admitted observation-error model. These are future acceptance cases, not tests run by this documentation PR. The [audit's exact checker](tools/check_proof_counterexamples.py) verifies selected rational facts of the existing counterexamples; it does not certify continuum bounds, a new predecessor backend or the historical MATLAB program.
