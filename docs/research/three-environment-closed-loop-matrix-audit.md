## Finding and task boundary

There is no delivered route that runs every module combination on one common closed-loop optimal-control task across Lotka–Volterra, Earth orbit, and fuel. There are useful delivered pieces: synthetic LV/fuel nonlinear feedback controllers; affine joint QP production; five nominal finite-action representation tracks; polyhedral forward/backward synthesis; geometry provider substitution; finite-table causal optimization. Their contracts differ in dynamics, objective, control domain, constraints, representations, and evidence. Connecting them requires explicit adapters and admission rules, rather than multiplying registry names.

The requested experiment has **one controller and no second player**. The common mathematical template should be finite-horizon deterministic control: observe the exact current execution state before each decision, solve the remaining problem to a fixed final time, apply the first zero-order-held input, advance the same physical model, and repeat. Pin one environment manifest per physical model, including initial state, admissible state/input sets, objective, observation timing, grid, and execution integrator. Different models have different dimensions and units; “same task” means this common formulation and protocol, with every compared configuration in an environment receiving identical inputs. It does not mean assigning identical numerical matrices or costs to physically different systems.

A solver's open-loop tail optimum, a locally stationary nonlinear program, an approximate set ranking, and a globally optimal feedback policy are different results. Report them separately. With deterministic known dynamics, full observation, and globally solved shrinking tails, Bellman's principle can connect tail optimization to the deterministic finite-horizon optimum. The present local NLP evidence does not establish that premise. No adversarial disturbance catalogue or minimax objective is needed for this request. Where an existing nominal adapter internally uses a singleton external input, that is an implementation reduction, not a second player ([nominal adapter](../../src/optimization/finite_action_nominal.cpp#L34)).

The older [comparison-program contract](../architecture/comparison-program.md) is a planning spec with evidence gates, not a current capability inventory or authorization to benchmark. In particular, its deferred nonlinear/feedback wording must not erase the newer delivered MPC11 code. Conversely, newer example code does not turn every comparison-program axis into a supported nonlinear feedback route.

## Representation support is route-specific

“Exact polytope” here denotes an unreduced finite V/strict-polyhedral mathematical representation. The fixed-plan and nominal APIs still advertise numerical assurance. It must not be used as shorthand for exact arithmetic, a complete nonlinear reachable-set proof, or a globally optimal closed-loop controller ([fixed-plan assurance](../../include/csl/reachability/fixed_plan_disturbance.hpp)).

| Representation | Delivered fixed-plan propagation | Relevant limit for a common constrained episode |
| --- | --- | --- |
| Exact polytope | Complete V candidate descriptions, possibly redundant; every initial/disturbance vertex pair propagated through affine stages | Has max-points capacity; unsafe successor rejects the whole plan, not clipping. Uses bounded V/singleton inputs and supported convex safety sets. Nonlinear images of a V hull are not established by vertex propagation. |
| Box | General-dimensional stagewise affine interval enclosure | Universal state constraints only; numerical outer trace. Generic ApproximationPort box producer's 1–2D limit is a different implementation contract. |
| Zonotope | General-dimensional generators, initial/disturbance V sets enclosed by boxes; generators added for numerical rounding | Universal state constraints only; explicit generator cap; no optimizer-completeness certificate. |
| Parallelotope | A fixed non-axis-aligned four-state frame and integer inverse | Four-state TwoPoints profile; not yet a general 2D LV or arbitrary-frame method. Four dimensions matching orbit/fuel do not validate a nonlinear model bridge. |
| Ellipsoid | General-dimensional, axis-aligned stage ellipsoid obtained through interval bounds and sqrt(n) enlargement | Universal state constraints only; different from the planar directional ApproximationPort producer. Not a general minimum-volume or freely oriented ellipsoid backend. |

Sources: [box](../../include/csl/reachability/finite_plan_box.hpp), [zonotope](../../include/csl/reachability/finite_plan_zonotope.hpp), [parallelotope](../../include/csl/reachability/finite_plan_parallelotope.hpp), [ellipsoid](../../include/csl/reachability/finite_plan_ellipsoid.hpp), [ellipsoid constraint admission](../../src/reachability/finite_plan_ellipsoid.cpp#L164). The physical bounds in the LV/fuel scenarios therefore cannot simply be passed to every approximate track today. Removing bounds to make a method run would define a different task. Keep the same constrained request and emit its scoped unsupported outcome until an adapter implements the required safety semantics.

Under exact full-state observations and deterministic dynamics, fixed-plan reachable sets collapse mathematically to singleton trajectories. This can be a useful smoke/degeneracy test, but it offers little evidence about approximation quality. Numerical widths must not be relabelled as physical uncertainty. A fixed nominal policy from one point does not establish a feedback advantage over an optimal open-loop plan on the exact deterministic execution; compare computational profiles separately from behavior on a declared off-trajectory policy domain.

The case/matrix contract must give each set an explicit mathematical-object role: (a) admissible-control forward reachable relation before selecting a policy, (b) backward target-feasibility/predecessor relation, (c) fixed-plan trajectory enclosure, (d) an initial-set ensemble under a named policy, or (e) parameter uncertainty under a declared information model. These roles must not be pooled in one accuracy table. Detect and retain degenerate cases: report singleton/rank-deficient stage sets, effective affine dimension and enclosure width; label a representation comparison uninformative when every mathematical set is a singleton. Prove predecessor recovery on nontrivial admissible-control sets before treating fixed-policy trace plots as reachable-set control evidence. A second explicitly named uncertain-initial-condition or observation-information study may exercise nontrivial sets while retaining a single controller, but it is a different information/task contract. Never introduce an adversary merely to make approximation plots more interesting.

## Why the Cartesian product is invalid

`StrategyConfiguration` contains strategy, LP, convex, hull, geometry, converter, approximation, selector and representation fields, but fields are not a promise that every strategy consumes every role ([definition](../../include/csl/synthesis/contracts.hpp#L305)). A configuration is a directed typed operation graph:

1. A physical model adapter selects its prediction model and discretization with declared error scope. Affine synthesis accepts affine stages, not arbitrary nonlinear callbacks. A physical model, affine surrogate, and sampled finite transition table need separate identities.
2. A route determines which roles are invoked. NMPC does not call hull reduction; direct QP does not become a hull comparison by populating a hull field. Inactive choices must be `not_applicable`, rather than separate counted attempts.
3. Each graph edge constrains input/output representation, dimension, assurance, relation (equivalent/inner/outer), objective and completeness. Phase I cannot minimize a quadratic, the planar ellipsoid adapter cannot accept a 4D set, and the fixed four-state parallelotope cannot represent 2D LV directly.
4. Exact/outer/inner set use changes optimization meaning. An outer candidate set can produce an unrealizable terminal optimum; an inner feasible set can miss a better controller. Use independently replayed applied actions and state feasibility, and retain the actual bound/estimate direction. A sampled hull has neither enclosure guarantee.
5. The registry still requires actual per-request capability admission, including generated intermediate requests. Advisory shape-envelope support does not waive concrete prepare checks. Selection/version failures and unsupported intermediates must stay attached to the requested graph, not trigger a silent substitute. [Registry types/admission](../../include/csl/registry/registry.hpp#L19), [prepared-provider implementation](../../include/csl/registry/provider.hpp#L89).

“All possible combinations” should consequently mean **every distinct semantically meaningful candidate graph over the audited module catalogue, with every graph classified and every supported graph attempted under an authorized budget**. Enumerate incompatible candidates as deterministic admission rows with a reason. Collapse inactive axes and record aliases to their canonical graph. Do not promise a finite run of every continuous orientation, direction, tolerance, action discretization or horizon; these require a pinned finite parameter catalogue.

## Coverage and outcome accounting

Create one immutable candidate row for `(environment manifest hash, episode protocol hash, prediction adapter/version, controller route/version, active module graph, finite parameter profile)`. Store action-domain and objective identity separately, so continuous and discretized controls cannot accidentally enter an equal-problem winner table. Canonicalize graphs before running: a hull axis absent from a QP route is inactive; two paths reaching the identical effective graph are aliases, not extra evidence.

First produce a complete **admission coverage** ledger: each meaningful candidate has runnable, unsupported-with-reason, or unresolved-adapter status. Then produce **attempt coverage** for runnable candidates: not-run-with-reason, completed, refused, failed, timed out, resource limited, cancelled, or incomplete. Keep verification orthogonal: verified for its explicit scope, incorrect on a sound counterexample, or inconclusive. A failed algorithm cannot be promoted by partial diagnostics. An approximate score cannot outrank an exact objective under a common “optimal” label.

For each completed episode report final independently replayed objective, sampled constraint violations, action sequence, solver/update count, complete/partial horizon, per-update and episode resource accounting, and evidence class. Plot 2D LV phase state and controls; orbit radius/radial-velocity and radius/angular-rate plus time traces; nonlinear fuel mass/flow pairs and controls. For linear fuel use its explicit flow/stock order. Label trajectories as trajectories; only plot reachable sets when their producer, physical/model scope and relation evidence support that label.

The [published-results gates](../architecture/published-algorithm-results.md) and [comparison independent-checker contract](../architecture/comparison-program.md#independent-checker-contract) continue to govern claims. Complete coverage is the retained classification of all meaningful candidates and attempts; it does not require every module to solve every environment, and it does not justify declaring a winner when tasks or evidence differ.
