# Separate sampling profile and source map

This is an independent limiter investigation; its timings are not part of `records.json`. A symbol-enabled `/Zi` build was profiled separately with Windows Performance Recorder CPU sampling and xperf symbol resolution. The workload executed 100 quiet reducer calls per fixture size (300 calls total), consumed the results, and suppressed per-call serialization and full certificate replay. It retains profile-run duration and LP-call totals in `raw-profile.jsonl`; the workload is therefore representative only of the reducer call path under these fixtures.

The raw WPR ETL and symbolized all-process exports are excluded from this repository artifact because they contain system-wide process activity. The retained `target-process-samples.csv` and `.json` include only `csl_hull_measure.exe` functions. Source-side symbol resolution identified HiGHS `equilibrationScaleMatrix` at 2.986% of this process's sampled weight, alongside `assessMatrix` and other HiGHS routines. Windows heap allocation/free/randomization functions account for 31.1% combined. Without call stacks those heap samples cannot be assigned to a specific source call path. The profile resolves likely areas for instrumentation; it does not say those shares are exclusive wall-time fractions.

The trace measured 109,051,904 bytes with SHA-256 `5dca8b8e9df0ecab0e5c612b493c8d7d2a460b376200e1c6347f147fb4cd155c`. xperf attributed 3,380,164 target samples out of 7,046,675 recorded samples (47.968%); reported target CPU usage was 6.13% over the trace. These values describe sampling attribution, not a speed metric. Sampling includes harness setup/output consumption, and provides neither stacks nor per-call phase timings.

Re-analysis requires the original system-wide ETL, deliberately omitted here. The retained source mapper is `../analyze_profile.py`; its inputs are a symbolized xperf CPU-sample export, `raw-profile.jsonl`, and the ETL whose SHA is recorded above. Rebuild profile binary separately from the Release timing executable and retain `/O2 /Ob2 /D NDEBUG /std:c++20`, adding `/Zi` and linker `/DEBUG`; never mix its data into the accepted timing rows. Source names were resolved against the profile executable's matching PDB.
